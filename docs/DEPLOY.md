# Deploying Shop Nest

The production setup is described in [`render.yaml`](../render.yaml) (a Render "Blueprint").
It has **not** been deployed: this page lists what to do, in order, when you decide to.

```
browser ──https──▶ shop-nest-web (public, Next.js) ──/api/*──▶ shop-nest-api (private, NestJS) ──▶ PostgreSQL
```

- Only the storefront is public. The API is a private service; everything (including Razorpay's
  webhook) reaches it through the storefront's `/api/*` proxy.
- Region: Singapore (closest to India). Plans in the file are the small paid ones; check
  Render's current prices before you start.
- The same Docker images are built and started by CI on every push (job "Docker images and
  compose"), so a green CI run means the images work.

## Before you start

| You need | Where it's used |
|---|---|
| A Render account connected to the GitHub repository | creating the Blueprint |
| A Brevo account, an API key, and a verified sender address | `BREVO_API_KEY`, `EMAIL_FROM_ADDRESS` |
| Razorpay **test** keys first (live keys only after testing) | `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET` |

## Steps

1. **Push** the `main` branch and wait for CI to be green (both jobs).
2. In Render: **New → Blueprint**, pick the repository. Render reads `render.yaml` and shows the
   database and the two services.
3. Fill in the secrets it asks for (`sync: false` entries): `BREVO_API_KEY`,
   `EMAIL_FROM_ADDRESS`, and the three `RAZORPAY_*` values (leave the webhook secret for step 6).
   `JWT_SECRET` is generated by Render; never reuse one from another environment.
4. **Apply**. Render creates the database, builds both images, runs
   `npx prisma migrate deploy` before the API starts, then starts the web service.
5. Open `https://shop-nest-web.onrender.com/robots.txt`, then the home page. If you use your own
   domain, add it to the web service and change `WEB_ORIGIN` on the API to match
   (`https://shop.example.in`): the API refuses browser requests from any other origin.
6. **Razorpay webhook** (Dashboard → Settings → Webhooks): URL
   `https://<web address>/api/webhooks/razorpay`, events `payment.captured`, `payment.failed`,
   `order.paid`, `refund.processed`, `refund.failed`. Copy its secret into
   `RAZORPAY_WEBHOOK_SECRET` on the API service.
7. **First admin.** Sign up on the live shop, then, from your computer, using the database's
   *external* connection string from Render (shown on the database page):
   ```bash
   cd apps/api
   DATABASE_URL="<external connection string>" npx tsx scripts/make-admin.ts you@example.com
   ```
   (Don't put that connection string in any file.)
8. **Test a real order** with Razorpay test cards/UPI, check the confirmation email arrives,
   refund it from `/admin`, and only then switch to live keys.

## Optional

- **Demo catalog:** `DATABASE_URL="<external connection string>" npm run db:seed -w @shop/api`
  from your computer. Don't run `db:seed-sales` on a real shop: it invents orders.
- **Monitoring:** see "Observability" in the README (error tracking and metrics are switched on
  by settings, not code changes).

## Rolling back

Render keeps previous deploys: **Manual Deploy → Rollback** on a service. Migrations aren't
rolled back automatically, which is why each one in this project only ever *adds* (new tables,
columns with defaults): the previous version of the code still works against the newer schema.
